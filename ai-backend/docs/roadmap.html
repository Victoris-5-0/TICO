The number, before the plan

The full roadmap is 26 person-days. Two people over eleven days is 22 slots — so the whole thing fits at about 9.5 hours per person per day. That is a hard sprint, not an impossible one, and the team has chosen it. Nothing below is cut. Section 03 shows exactly which stretches carry the overload, so you can see the crunch coming instead of discovering it.

The one thing that makes or breaks the split

Agree the Pydantic DTOs in schemas/ together, on day one, before either of you writes anything else. They are the contract between the two lanes. Get them right and you will barely block each other for eleven days; skip it and you will spend the week merging. Only one person — Ahmed — ever runs alembic revision.

Deploy on day 3, not day 11

The EC2 deploy is scheduled for 6 September with nothing but /health on it. Nginx, Gunicorn, systemd and TLS always take longer the first time, and discovering that on 14 September is how a working backend fails to reach a judge. Get the pipeline working while it is cheap, then redeploy all week.

Section 03

Where the load actually falls

The overload is not spread evenly. Four stretches have slack; three are over. Knowing which is which lets you spend the long nights where they buy something.

StretchNeedsSlotsLoad
M0 — Foundations · 4–5 Sep24Comfortable. Use the slack to get the EC2 deploy done early.
M1 — Evidence · 6–7 Sep34Comfortable.
M2 + M3 · 8–10 Sep64Over by 2. The hint pipeline and the classifier land together.
M4 — Adaptation · 10–12 Sep64Over by 2. Mastery, planner, composer and the escalation layer.
M5 — Generation · 13 Sep54Over by 1. And it is the milestone most exposed to an external blocker.
M6 — Chat + arena · 14–15 Sep44Exactly full, with submission on the same day.

The real risk is not your hours

You can work 9.5-hour days. What you cannot do is work through a blocker that belongs to someone else. Every stretch that is over-loaded also depends on something a teammate owes you — the error enum for M3, level_concept.weight for M4, and the prop verbs for M5. If any of those arrive late, the overload compounds into the next stretch and there is no slack left to absorb it. Chase them from day one, not from the day you need them.

Triage order, if a blocker does land

Not a plan to cut — a decision already made, so nobody has to make it at 2am on the 14th. If something has to give, give it in this order:

  1. Worlds 2 and 3. Ship generation in Cairo Metro alone. The mechanism is identical, so this costs almost nothing on stage.
  2. The challenge arena. Leave it a locked nav item. TICO chat is the better half of M6 to keep.
  3. The escalation review layer. Composer and planner fall back to rules-only. Adaptation still works and is still visible; it just loses its second opinion.
  4. The classifier becomes string matching. Hand-written rules over common error text. Hints get slightly less specific.

M1 is never on this list. Skipping the evidence layer to move faster is the one shortcut that cannot be undone — every milestone after it reads from those tables, and data you did not record is data you can never recover.

A parallel track that must start on day one

The world manifests are content work, not backend work, and M5 cannot start without them. Three files — Cairo Metro, Cairo Traffic, and the third world — each listing scenes, characters, props and the exact verbs the student's code may call. The verbs must come from whoever builds the game engine. Start this at M0 and run it alongside everything else; a worked example is at content/worlds/cairo_metro.yaml.

Section 04

The milestones in detail

M0

~2 days

Foundations

The Sanjeev course skeleton, plus the one thing his course doesn't have: a schema boundary that stops two developers destroying each other's migrations.

  • git init, push, branch protection on main
  • app/ skeleton: main.py, config.py, database.py, api/v1/
  • requirements.txt pinned; venv documented in the README
  • Supabase via the session pooler; GET /health does a real DB round-trip
  • Create the ai Postgres schema
  • Alembic with version_table_schema="ai" + include_object filter
  • Supabase JWT verification and per-request ownership checks in core/auth.py
  • GitHub Actions: pytest on every push

Exit criteria A teammate can clone, alembic upgrade head, run the server and hit /health with a real JWT. Autogenerate produces an empty migration — proving it cannot see game tables.

depends on: nothing — start today

M1

~3 days

The evidence layer

All eight tables and the session lifecycle everything else hangs off. Nothing here is intelligent yet — that is the point. Build the recorder before the reasoner.

  • ORM models + first migration for the eight ai tables, including student_lesson_plan
  • level.is_skippable agreed with the game dev — which lessons may never be optional
  • Read-only views onto user, level, concept, code_submission
  • level_concept.is_primary and .weight agreed with the game dev and populated — the join cumulative learning depends on
  • concept.sequence_order populated: variables → conditionals → loops → functions
  • POST /v1/sessions and session close
  • ai_interaction logging helper, wired so no model call can bypass it

Exit criteria A fake playthrough can be written end to end by test code: session opens, submissions and hints record against it, session closes with a duration. Query the rows and reconstruct what happened.

depends on: M0 · needs the concept list and level_concept weights

M2

~4 days

TICO hints — the first thing worth showing

The design rule made real in one endpoint. The server picks the rung; TICO only writes that rung's prose.

  • domain/hint_ladder.py — 4 rungs, pure function, fully unit-tested, no DB
  • ai/router.py with the Gemini map, and ai/prompts/ with a version string
  • TICO's persona prompt: warm, Egyptian Arabic dialogue, English identifiers
  • ai/chains/tico_hint.py — with_structured_output(), one call, gemini-3.5-flash-lite
  • ai/guards.py — Pydantic validation, retry once, authored fallback
  • Postgres hint cache on (level_id, rung, error_category, scaffold_state) — P0, not optional
  • POST /v1/hints end to end, writing hint_event
  • Hint leak test in CI, graded by rung: 1–2 no solution identifier, 3 none of the student's target values, 4 no complete runnable line
  • Authored fallback hints for all four rungs
  • Per-student daily call cap in middleware

Exit criteria A stuck student gets escalating help from TICO across four rungs, the ladder never skips, no rung ever emits a complete solution, and a repeat request on the same error is served from cache with no model call. Demo-able.

depends on: M1 · unblocked — ladder length and provider both settled

M3

~2 days

Code analysis

Turns a failed submission into a labelled error category — what makes hints specific rather than generic, and what feeds mastery in M4.

  • Agree a fixed error-category enum with the game team
  • ai/chains/classify_error.py — small structured output
  • POST /v1/submissions/analyze, writing error_category back
  • Feed error_category into the M2 cache key
  • Classifier eval — 30 hand-labelled wrong submissions, accuracy tracked

Exit criteria Accuracy measured and written down. Hints visibly improve because they now know why the code is wrong.

depends on: M1 · can run in parallel with M2

M4

~6 days

Student model, planner and composer

Where the platform stops being a quiz with hints and starts being adaptive. Every decision here follows the same shape: a pure-Python rule proposes, and a model reviews the risky calls.

  • domain/mastery.py — mastery and confidence from attempts, hints, time. Pure, no model
  • Weighted updates: target concept at full weight, each carried concept at its level_concept.weight
  • domain/plan.py — proposes required / optional per lesson from the diagnostic, with a confidence
  • domain/composer.py — scaffold plan per carried concept, difficulty params, reps, advance-or-hold
  • The escalation layer — a model reviews every proposed skip and every conflicting composer decision; writes decided_by and reason
  • services/planner.py + POST /v1/students/{id}/plan — beginner path and diagnostic path
  • services/student_model.py + POST /v1/students/{id}/refresh, background on session close, including forward re-planning
  • Planner safety eval — assert nothing below threshold is skipped, and is_skippable = false lessons are never optional
  • Composer eval — assert a weak carried concept is never scaffolded away entirely

Exit criteria Two synthetic students — a beginner and an experienced one — get visibly different paths from the same diagnostic, and two students at the same lesson get visibly different scaffold plans. Every skip has a logged reason you can read.

depends on: M1, M3 · the largest milestone after M5

M5

~5 days

Mission generation — MVP complete

Closes the loop. The roadmap fixes the concept and the world; the composer fixes the difficulty and the scaffolding; generation composes the scenario from the inventory against both.

  • Manifest loader + mission_template rows projected from the three world files
  • ai/graphs/mission_gen.py — generate → validate → repair ×2
  • The validator — every scene, prop and verb exists in the manifest; the solution passes its own tests; the target concept is actually present
  • generated_mission.validated set by the validator, never by the model
  • Reuse: an equivalent params + scaffold combination returns the existing row
  • POST /v1/missions/next — the full pipeline in one call
  • Generation legality eval in CI over all three worlds

Exit criteria Two students at the same lesson get two different scenarios in the same world, each matched to their scaffold plan, each solvable, and neither referencing anything outside the manifest.

depends on: M4 · blocked until the three world manifests exist

M6

~4 days

TICO chat and the challenge arena

The conversational mentor and the post-roadmap arena. Scheduled for 14–15 September, landing alongside submission — the tightest stretch in the plan.

  • ai/graphs/tico_chat.py — Postgres checkpointer, thread_id = mission_session.id
  • Checkpoint tables in a langgraph schema Alembic ignores
  • POST /v1/tico/messages with SSE streaming
  • Input moderation before any student text enters a prompt
  • POST /v1/challenges/next — mastered concepts mixed, no scaffolding, shorter ladder
  • Challenge results write mastery for every concept touched

Exit criteria A student holds a conversation with TICO that remembers the mission, and a student who finished the roadmap gets a mixed-concept challenge with no scaffolding.

depends on: M5

Section 05

Decisions — all settled

Every build decision was closed on 4 September. Nothing in this plan is waiting on an answer from inside the AI pair.

DecisionSettled as
Hint ladder length4 rungs. Orient → question → name the concept with a foreign example → walk to the fix in words. No rung ever emits a complete solution; after rung 4 comes a mini-practice.
Model providerGoogle Gemini. gemini-3.5-flash-lite for hints, NPC lines and classification; gemini-3.5-flash for escalation review, generation and chat. No -preview models, no gemini-2.5-*.
Editor languagePython. Manifest verbs, starter code and hint prose are all Python.
Alembic ownershipAhmed. Nobody else runs alembic revision — not the game developer, not the AI teammate.
Pydantic schemasAhmed writes them; the AI teammate builds against whatever they say.

One open item remains, and it belongs to someone else: level_concept weights — who sets them, needed before M1. That sits in section 06 with the rest of the external dependencies.

One consequence of choosing Gemini

Prompt caching will not carry the cost story: Gemini's context caching targets large contexts and has minimum-token thresholds that short hint prompts will not reach. The Postgres hint cache is promoted from an optimisation to a requirement and is now the primary cost lever — it stays on the 8th, at P0. Also check the rate limit on whichever tier the API key sits on; a per-minute cap tripping mid-demo is indistinguishable from a broken service.

The five things most likely to go wrong

RiskWhy it bitesMitigation
The manifests aren't readyM5 is the largest milestone and cannot start without them. They depend on the game engine developer, not on you — which makes it the easiest deadline to miss.Start the manifests at M0 as a parallel track. Get the prop verbs in writing early, even as a draft.
Duelling Alembic migrationsTwo developers autogenerating against one Supabase project produce drop-table migrations for each other's work. The classic way a student team wrecks its database before a demo.The ai schema split at M0. Verify by running autogenerate and confirming an empty migration.

A generated mission is unsolvableIf generation invents a verb the engine doesn't implement, a child is stuck on something impossible — and it will happen live.The validator at M5 re-reads the manifest and runs the solution against its own tests before anything ships.

If the deadline is tighter than the track

Cut M6 entirely, then trim M3 to a rule-based classifier with no model. If M5 is at risk, ship one world manifest instead of three — generation working in Cairo Metro alone still demonstrates the whole mechanism. Never cut M1. Skipping the evidence layer to reach hints faster is the one shortcut that cannot be undone: every milestone after it reads from those tables, and data you didn't record is data you can never recover.
