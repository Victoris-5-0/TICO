Section 04

How the client integrates

Written for whoever owns the Next.js side. The Python service returns JSON decisions only — it never renders game state and never executes student code.

1. Generate the types, don't hand-write them

FastAPI publishes an OpenAPI spec from the same Pydantic models the service validates with, so the types cannot drift:

npx openapi-typescript https://<ai-backend>/openapi.json -o client/src/lib/ai-api.d.ts

Re-run it whenever the backend says a contract changed. Browse /docs for the interactive version.

2. Call it from the server, not the browser

Put the AI calls behind Next.js route handlers or Server Actions. Two reasons: the browser never needs to know the backend URL, and the JWT stays server-side.

// client/src/lib/ai.ts
export async function getHint(token: string, body: HintRequest) {
  const res = await fetch(`${process.env.AI_BACKEND_URL}/v1/hints`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${token}`,
    },
    body: JSON.stringify(body),
  });
  if (!res.ok) throw new Error((await res.json()).detail);
  return res.json() as Promise<HintResponse>;
}

3. Auth

Every request carries Authorization: Bearer <token>. The service verifies it and extracts the user id — the student is never named in a request body. A 401 means the token is missing, expired or malformed; a 403 means the token is valid but belongs to a different student than the session being asked about.

TICO chat is the one that is different

/v1/tico/messages streams Server-Sent Events. It is not await res.json() — you need a streaming reader that appends each delta as it arrives. Budget real time for it, and build it against the stub early rather than discovering the shape on the 14th.

const res = await fetch(url, { method: "POST", headers, body });
const reader = res.body!.getReader();
const decoder = new TextDecoder();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  // each frame: { delta, done, blocked?, offered_hint_rung? }
  appendToBubble(decoder.decode(value));
}

5. Errors, and what to show a child

Every failure returns { "detail": "...", "code": "..." }. detail is safe to show a student — it is written for a ten-year-old, never a stack trace.

A student mid-mission should never see a 500. If a model call fails, the service falls back to an authored hint and still returns 200. If you do get a 5xx, show a friendly retry rather than an error code.

6. What the client still owns

  • Running the code. The AI service never executes student Python. Run it, then send the results to /submissions/analyze.
  • All rendering. The service returns a brief, starter code and tests — not markup.
  • Plain data reads. Tracks, lessons, progress and XP come from Prisma directly. Do not proxy those through the AI service; it adds a hop for nothing.
