# TICO - Agent Guidelines & Architecture Rules

TICO is an intelligent programming companion platform. The repository is a monorepo with three primary root areas:

- `client/` — Next.js frontend plus TypeScript server/backend code, Prisma, and web assets.
- `ai-backend/` — Python AI service and AI-specific orchestration/inference code.
- `docs/` — architecture, product, API, and implementation documentation.

All contributors and AI agents must keep these boundaries clear. Do not place Next.js application code at the repository root, and do not mix Python AI service code into `client/`.

## Required Reading Before Work

Every agent must read [the documentation map](docs/README.md) and then the documents for its work lane before editing code. At minimum:

- Product, curriculum, or content: `docs/01-product-and-game-design.md`, `docs/02-python-curriculum.md`, and `docs/03-egypt-world-bibles.md`.
- Client/UI: `docs/04-ux-design-and-localization.md`, `docs/05-system-architecture.md`, and `docs/10-safety-privacy-and-security.md`.
- Database or cross-service contracts: `docs/05-system-architecture.md` and `docs/06-data-model-and-contracts.md`.
- Browser execution: `docs/07-browser-python-runner.md`.
- AI backend: first read `ai-backend/AGENTS.md`, then the AI reading list defined there.
- Assets: `docs/09-asset-bible-and-image-prompts.md`.
- Testing, operations, or delivery planning: `docs/11-testing-and-operations.md` and `docs/12-roadmap-and-agent-playbook.md`.

`docs/decisions/0001-mvp-baseline.md` records settled MVP decisions. A change that contradicts it requires an explicit product decision and a superseding ADR; do not silently diverge in code.

## 1. Tech Stack & Tooling

### Client
- Next.js 16 (App Router, Turbopack, React 19)
- TypeScript in strict mode
- Tailwind CSS v4
- PostgreSQL + Prisma ORM
- `pnpm` only; never use npm or yarn

### AI Backend
- Python 3.11+
- Keep AI provider integrations, agents, model orchestration, evaluation, and AI API endpoints inside `ai-backend/`.
- Add Python dependencies to the AI backend only; do not add Python packages to the Next.js client.

## 2. Repository Structure Rules

```text
TICO/

├── ai-backend/      # Python AI backend
├── docs/            # Project documentation
├── AGENTS.md
```

- Run Next.js and Prisma commands from `client/` unless a root workspace command explicitly proxies them.
- Keep shared contracts documented in `docs/` when both `client/` and `ai-backend/` depend on them.
- Prefer HTTP/API boundaries between the Next.js client/backend and Python AI backend instead of cross-language filesystem coupling.

## 3. Database Architecture & Rules

### Prisma Client Singleton
- Location: `client/src/lib/db.ts`
- Never instantiate `new PrismaClient()` directly in API routes, Server Actions, or components.
- Import the shared instance with `import { db } from "@/lib/db";`.

### Schema Management
- `client/prisma/schema.prisma` is the single source of truth for every application and AI table.
- All tables currently live in the shared PostgreSQL `public` schema. There is no separate AI-owned database schema.
- Prisma owns all migrations. The Python service maps these tables with SQLAlchemy for reads and writes but never creates or migrates them; do not add Alembic.
- After schema changes, from `client/` run `pnpm db:generate` and create/apply the appropriate migration.
- Never manually alter production tables without matching Prisma migrations in `client/prisma/migrations/`.
- Use explicit snake-case table and column mappings so Prisma and SQLAlchemy stay aligned.
- Never run `prisma migrate reset` against the shared database.

### Prisma Configuration
- Prisma config lives at `client/prisma.config.ts`.
- Do not add Prisma database or seed configuration under a `prisma` key in `package.json`.

### Transactions
Use `db.$transaction(...)` for multi-table mutations that must succeed atomically.

## 4. Environment Variables & Security

- Client environment template: `client/.env.example`.
- Never commit `.env` files or credentials.
- When adding client env vars, update `client/.env.example` with sanitized placeholders.
- AI backend secrets belong to AI backend environment configuration and must not be exposed through `NEXT_PUBLIC_*` variables.

## 5. Next.js App Router Conventions

- Server Components by default.
- Add `'use client'` only where client state, hooks, or browser event handlers are required.
- Keep client component boundaries small.
- Put Server Actions in `client/src/actions/` or co-locate them with explicit `'use server'` directives.
- Validate mutation inputs before database operations.
- `@/*` maps to `client/src/*` from within the client project.

## 6. Documentation

- Put architecture decisions, API contracts, setup guides, and product/implementation notes in `docs/`.
- Update relevant docs whenever a change modifies an interface between `client/` and `ai-backend/`.
